# 2026-10-23 - Day 1

## Checkpoint 0.1 - Walking skeleton

**Goal:** a runnable API with typed config and a liveness endpoint, before any
infrastructure exists.

**What was built**

- `pyproject.toml` with Python 3.12 pinned via `uv`
- `packages/helix/config.py` - settings loaded from `HELIX_*` env vars
- `apps/api/main.py` - `GET /health/live`, `GET /`
- `tests/test_health.py`
- `Makefile` with `sync`, `dev`, `test`, `lint`, `fmt`, `ci`

**Why this shape**

- Config is typed and environment-driven (12-factor). No hardcoded URLs, so the
  same image works locally and in Compose.
- `/health/live` answers one question only: is the process serving? Dependency
  checks belong in `/health/ready` (checkpoint 0.2), because a liveness probe
  that fails on a slow dependency causes restart loops.

**Test**

```bash
make sync
make dev
curl -s localhost:8000/health/live | jq
make test
make lint
```

**Interview angle**

- Liveness vs readiness: liveness = "restart me", readiness = "send me traffic".
- Why typed settings beat `os.getenv` everywhere: validation at startup, one
  source of truth, easy to test.

## Doubts from 0.1 (answered)

- Why async Python? → I/O waits vs CPU work; async for I/O, processes for CPU.
- What is a Makefile? → named tasks + one interface for humans and CI.
- What do `local` / `dev` / `test` / `staging` / `prod` mean? → conventions;
  behavior changes only where code branches, now validated with `Literal`.
- What are log levels? → severity filters; INFO shows INFO and above.
- Why the `asynccontextmanager` warning? → annotate with
  `AsyncGenerator[None, None]`, not `AsyncIterator[None]`.

Full answers: [[Foundations]]

## Checkpoint 0.2 - Local stack and readiness

**Goal:** Postgres, Redis, Qdrant, and MinIO start with one command, and
`/health/ready` reports each dependency truthfully.

**What was built**

- `infra/docker-compose.yml` with healthchecks, named volumes, and
  localhost-only port bindings.
- MinIO mapped to `9100/9101` because Portainer owns `9000/9001`.
- `packages/helix/health.py` - concurrent checks with 1.5s timeouts.
- `GET /health/ready` - 200 when all dependencies are up, 503 with the failed
  names when one is down.
- Compose targets in the Makefile: `up`, `down`, `reset`, `ps`, `logs`, `ready`.
- Integration test marker and `make test-integration`.

**Verified manually**

- All four containers healthy.
- `make ready` -> 200 with all checks `ok`.
- `docker stop helix-qdrant` -> 503 with `qdrant: down`.
- `docker start helix-qdrant` -> 200 again.
- MinIO console responds on `9101`.

**Notes / caveats**

- MinIO's official images are unavailable; the Compose file uses a pinned
  community mirror for local dev only. Production would use the official
  distribution or managed S3.
- `make reset` deletes volumes. `make down` keeps them.

Full write-up: [[Compose-Stack]]

## Doubts: storage layers and GUIs

- How do I see what is in Postgres? → Adminer at `:8081`, DBeaver desktop, or
  `psql`.
- Why Redis when we already have Postgres and Qdrant? → queue, cache, rate
  limits, locks. Ephemeral speed, not source of truth.
- Why did `:6333/` look empty? → that is the API metadata endpoint; the UI is
  `/dashboard`.
- Why MinIO? → large raw blobs belong in object storage, not a relational DB or
  a vector index. S3 API gives a clean path to AWS S3/R2.
- GUIs added under the `tools` profile: Adminer (`:8081`) and RedisInsight
  (`:5540`); Qdrant and MinIO already ship UIs.

Full answers: [[Storage-Layers]]

## Process - checkpoint checklist

**Problem:** the plan is long enough that either the agent or the human can skip
a step (tests, notes, commit, manual verification).

**Decision:** one versioned checklist with two layers:

- a **roadmap** row per checkpoint, and
- a **Definition of Done** for the current checkpoint.

The agent marks implementation, tests, docs, CI, and commit. The user alone
marks `User verified` after replying `pass`. This prevents the agent from
self-certifying a checkpoint.

`make checklist` parses the file and prints the current checkpoint, remaining
items, and roadmap counts. The file is the source of truth; the HTML guide will
be generated from it later.

See [[Checklist]] and [[Foundations#8. Process: definition of done]].
