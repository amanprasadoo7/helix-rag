## Checkpoint 0.5 - CI baseline

**Goal:** run the same quality gate locally and on GitHub, without duplicating
the Ruff, mypy, and pytest commands in YAML.

**What was built**

- `.github/workflows/ci.yml`
- Runs on pushes to `master`, pull requests, and manual dispatch
- Uses Python 3.12 and uv, with caching keyed by `uv.lock`
- Runs `uv sync --locked` and then `make ci`
- Read-only token, concurrency cancellation, and a 10-minute timeout
- `CI-Baseline.md`, checklist, README, and `AGENTS.md` updated
- Fixed `scripts/checklist.py` to parse both compact and aligned roadmap tables
- Added `tests/test_checklist.py` for both table shapes

**Verified manually**

```bash
make ci
# Ruff and mypy pass; 37 passed, 1 deselected

docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest
# no output: workflow syntax and expressions are valid
```

**Decisions**

- CI calls `make ci` instead of repeating the commands. One definition means
  local and remote gates cannot drift.
- The baseline is unit-only. Integration tests need Postgres, Redis, Qdrant, and
  MinIO, so they stay a separate concern.
- The workflow runs one Python version because the project supports one.
- Action versions are pinned to release tags for now; full SHA pinning and an
  updater can come later.

**Verified**

- Local `make ci` green: Ruff, mypy on 10 files, 37 passed / 1 deselected.
- Remote run `CI / lint and test` succeeded on `master`
  ([run 40125057288](https://github.com/amanprasadoo7/helix-rag/actions/runs/40125057288)).
- User replied `pass`, so the checkpoint is closed and the roadmap row moved to
  `done`.

## Checkpoint 1.1 - Parser

**Goal:** convert each of the 2,500 pinned Markdown files into one stable
document model, so later stages read structured JSON instead of re-parsing
Markdown.

**What was built**

- `packages/helix/parsing.py`: Pydantic document model plus the native parser
- `scripts/parse_corpus.py`, `make parse`, and `make parse-sample`
- `tests/test_parsing.py`: 13 cases covering frontmatter, heading tree, code,
  lists, tables, callouts, shortcodes, HTML, determinism, and warnings
- `docs/helix-brain/01-Architecture/Parsing.md`
- `docs/adr/0001-markdown-parser.md`
- `pyyaml` and `types-PyYAML` added as direct dependencies

**Result**

```text
Parsed 2500 documents: 37614 sections, 113255 blocks,
3565493 words, 12408 code blocks, 7280 tables, 26 warnings
```

All 2,500 files parsed; zero failures. The run takes about 13 seconds and writes
about 122 MB of pretty-printed JSON to `data/parsed`. The 26 warnings are pages
whose entire body is a dynamic shortcode (for example a generated team list), so
there is no static text to index.

**Manual test**

```bash
make parse-sample
# five evenly spaced documents, one summary line each
python3 -m json.tool \
  data/parsed/handbook/content/handbook/business-technology/enterprise-applications/guides/zuora-collect.json \
  | less
# title, 36 sections, 86 blocks; headings match the source
```

**Decisions**

- Native Markdown parser now; Docling deferred until a non-Markdown source
  exists. The corpus has no PDFs or HTML files, so Docling would add models and
  runtime without improving accuracy.
- A heading tree with breadcrumbs, not a flat list, because the chunker needs
  parent scopes and citations need a readable path.
- `text` is normalized for retrieval and `raw` keeps the source excerpt. The
  output is larger, but the next stage never has to guess what the source said.
- Dynamic shortcodes are removed; empty pages produce a warning instead of
  inventing content.
- The parser allows indented fences so code inside list items stays code. That
  fixed 53 false "unclosed fence" warnings in the first full run.

**Open**

- The golden set still has seven seed cases; parsing does not change it.
- Nested lists are flattened in `text` (levels remain in `meta`). Revisit only
  if chunking quality shows the hierarchy matters.
- User verification remains.
