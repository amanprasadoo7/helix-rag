## Checkpoint 1.2 - design conversation

The ACL classifier was explained in plain language and then at the rule level.
The important correction was that permissions are attached to **documents**, not
chunks: if every chunk from a document inherits the document's label, there is no
way for one chunk to leak while its sibling is protected.

The role model is an additive set, not a hierarchy. `authenticated` is the public
sentinel, `employee` is the internal baseline, functional roles are added on top,
and `admin` is break-glass.

## Decisions

- Classify by source and path, not by content or tags.
- Use the expanded taxonomy: public, internal engineering, internal company,
  restricted security, confidential HR, confidential finance, confidential legal.
- Unknown paths default to `restricted:unknown` with no roles.
- Longest matching prefix wins, with boundary-safe matching.
- Store `rule_id`, `matched_prefix`, and `reason` for audit, plus a top-level
  `policy_version`.
- Write a sidecar ACL index under `data/acl`; leave parsed JSON untouched.
- Add `1.5b` MinIO raw + manifest snapshot after 1.5.
- Defer tag overrides such as `project:atlas`.
- Add `1.7` eval seed expansion before retrieval tuning.
- Add `2.0` identity context and a localhost-only trusted role resolver before
  the 2.2 ACL pre-filter.
- Move `business-technology` to `internal:company`; treat `billing` as an alias
  for `finance`.

## Doubts answered

- **Why MinIO after 1.5?** It is useful but not required to make search work.
  Archiving raw bytes and the manifest is a snapshot concern, so it gets its own
  small checkpoint after the retrieval stores exist.
- **Why not a simple `internal` label?** The demo needs visibly different access
  outcomes. The four sensitivity prefixes make the security behavior legible in
  the UI and in evals.
- **Why not one `reason` string?** The structured fields separate policy identity,
  matched path, and prose explanation. That is what makes a misclassification
  debuggable.
- **Why can a user have multiple roles?** People wear several hats. A set
  intersection is easier to test than a role hierarchy.
- **What about duplicates?** The parser overwrites a deterministic path; the ACL
  index rejects duplicate `(source, path)` keys. Content-level dedup waits for
  1.6 hashes and tombstones.

## Checkpoint 1.2 - implementation

**Goal:** label every manifest-selected document with a classification and the
roles allowed to retrieve it, using a deterministic source-and-path policy that
denies unknown paths.

**What was built**

- `packages/helix/acl.py`: `Role`, `Classification`, `Rule`, `AclPolicy`, and
  `AclDecision`; boundary-safe longest-prefix matching; `billing` -> `finance`
  normalization; `AclDecision.allows` for the later retrieval filter.
- `scripts/classify_corpus.py`: reads `data/manifest.json`, rejects duplicate
  `(source, path)` keys, and writes `data/acl/index.json` plus `summary.json`
  with `policy_version`, manifest SHA-256, and counts by classification, rule,
  and source.
- `make classify` and `make classify-sample`.
- `tests/test_acl.py`: 21 tests covering the taxonomy, source distinction,
  prefix boundaries, longest-prefix and tie behavior, the role matrix, alias
  handling, unknown deny, duplicate keys, deterministic output, and a
  full-corpus check that runs when the manifest is present.

**Verified manually**

```bash
make classify-sample
make classify
```

Result: 2,500 documents, 0 unknown, with counts matching the reviewed table:
`public:docs` 1,500, `internal:eng` 439, `internal:company` 383,
`restricted:security` 103, `confidential:hr` 28, `confidential:legal` 28,
`confidential:finance` 19. A second full run produced identical SHA-256 hashes
for both sidecar files.

**Decisions**

- Keep the policy in code, not the manifest, so the reviewed table is versioned
  with the classifier.
- Store no timestamp; use the manifest hash for traceability and determinism.
- Keep duplicate prefix rules legal so equal-length ties resolve by table order;
  duplicate rule ids are rejected as a configuration bug.
- Leave parsed JSON untouched and write a sidecar index under `data/acl`.
